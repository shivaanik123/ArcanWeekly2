## Overview

This session focused on centralizing historical data extraction from weekly reports into Parquet files, eliminating the need for fake/generated data in the dashboard graphs.

---

## What Was Done

### 1. Historical Data Pipeline

Created a complete pipeline to extract historical data from weekly reports and store in Parquet format.

**New Scripts:**
- `scripts/sync_bucket.sh` - Syncs S3 bucket to local `bucket_copy/`
- `scripts/backfill_historical_data.py` - Extracts historical data from weekly reports to Parquet

**Key Files Modified:**
- `components/graphs.py` - Refactored from 1339 lines to 336 lines, now pulls from Parquet
- `utils/local_data_service.py` - Added methods to read Parquet files for graphs

### 2. Two Weekly Report Formats Supported

**Internally Managed (INPUT sheet)** - 10 properties:
- 55 Pharr, Capella, Colony Woods, Emerson 1600, Hamptons at East Cobb
- Haven, Manchester at Weslyn, Marsh Point, Tall Oaks, The Hangar

**Externally Managed (Occupancy + Financial sheets)** - 9 properties:
- Abbey Lake, Georgetown, Kensington Place, Longview, Marbella
- Perry Heights, Portico at Lanier, The Turn, Woodland Commons

### 3. Auto-Detection of Column Layouts

The INPUT sheet has three column variants (detected automatically by finding "Date" headers):

| Format | Rent Date Col | Work Orders Date Col | Example Property |
|--------|---------------|---------------------|------------------|
| A | 42 | 46 | 55 Pharr |
| B | 41 | 45 | Capella, Haven, etc. |
| C | 40 | 44 | Colony Woods |

### 4. Data Extracted

From weekly reports, the following is extracted to Parquet files:

| Data Type | Internal (INPUT) | External (Occ+Fin) |
|-----------|------------------|-------------------|
| Occupancy % | cols 12-13 | Occupancy sheet cols 13-16 |
| Leased % | - | Occupancy sheet col 15 |
| Projected % | - | Occupancy sheet col 16 |
| Work Orders | cols 44-48 (varies) | Occupancy sheet col 18 |
| Make Readies | cols 44-48 (varies) | Occupancy sheet col 17 |
| Revenue | col 19 | Financial sheet col 15 |
| Expenses | col 22 | Financial sheet col 16 |
| Market Rent | cols 40-44 (varies) | Financial sheet col 13 |
| Occupied Rent | cols 40-44 (varies) | Financial sheet col 14 |
| Collections | cols 29-32 | Financial sheet cols 18-19 |

## What Needs to Be Done Next

### 1. S3 Bucket Alignment

The `historicaldata/` folder needs to be uploaded to S3:

```bash
aws s3 sync bucket_copy/historicaldata s3://arcan-dashboard-data-dev-408312670144/historicaldata --profile Arcan
```

Consider adding this to `sync_bucket.sh` or creating a separate upload script.

### 2. Production Data Service

Currently `LocalDataService` reads from local `bucket_copy/`. For production on Elastic Beanstalk:
- Either sync historicaldata at deploy time
- Or update LocalDataService to read directly from S3 (like it may do for weekly reports)

### 3. Automation (Future)

Options for automating the backfill:
1. **Lambda trigger** - Run backfill when new weekly reports are uploaded
2. **Scheduled job** - Weekly cron to regenerate Parquet files
3. **Deploy-time** - Run backfill as part of EB deployment

### 4. Missing Property: Tapestry Park

Tapestry Park exists in earlier weeks but not in 11_16_25. Check if:

- Needs manual investigation

### 5. Data Quality Checks

- May need to check if older weekly reports exist in S3

### 6. Graph Component Cleanup

`graphs.py` still has some unused code paths. Consider:
- Further simplification

## Notes

- Weekly reports aggregate historical data, so only the latest report is needed for backfill
- Property names must match folder names in S3 (not filenames which may differ)
- The backfill auto-detects the latest week folder with property subfolders
- Parquet files are organized by property/year for efficient querying
